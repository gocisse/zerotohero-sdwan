| 24 | Topic accuracy: last 10 answers, linear recency weights (newest = n), weak < 70% with >= 3 answers | Recent performance dominates but one lucky answer cannot hide a pattern; mirrors the 70% quiz threshold. |
| 25 | Content ids are the source of truth; orphaned DB rows are ignored and never deleted | Content can be restructured without breaking progress; restoring a removed id brings its history back. |
| 26 | Added a second placeholder section (`01-sample-two`) | Needed to exercise "skip / continue to the next section" with a real next section; clearly marked placeholder. |
| 27 | Diagrams are declarative YAML (`content/diagrams/*.yaml`), not hand-written SVG per lesson | One renderer gives every diagram the same icons, link styles, legend, dark mode, responsive scaling, step player, accessibility and reduced-motion handling; authors write nodes/links/steps instead of coordinates-and-paths; diagrams stay reviewable as small diffs and can be validated; a design change (e.g. a new link look) is made once. | 28 | Diagrams, glossary and component references are validated server-side at startup (and on reload) | The same fail-loudly rule as lessons: a typo in a node id or a `<Term id>` is reported with file and line before it can reach a reader, all errors at once, with `make validate-content` for authoring.
