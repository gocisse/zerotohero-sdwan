**By the end of this lesson you will be able to:**

- create, duplicate, modify and delete a <Term id="profile">Profile</Term> with the documented steps;
- name the Profile page's tabs and the Profiles list's columns;
- say how a Profile reaches an Edge and what the documentation says about a Profile change;
- say what is documented about the <Term id="quick-start-profile">Quick Start Profile</Term> and what is not.

## The documented steps

- **Create.** Configure > Profiles > **New Profile**, "Enter a name and description for the new Profile and select Create". The Device tab opens.
- **Duplicate.** Select a Profile and choose **Duplicate**, or on the Profile page **Shortcuts > Duplicate Profile**, which opens a Copy Profile dialog.
- **Modify.** Select a Profile and choose **Modify**, or **Shortcuts > Modify Profile**. The **Overview** tab's **EDIT** changes the Profile Name, Description and Local Credentials. Changes on the Device tab need **Save Changes**.
- **Delete.** **More > Delete**, or Shortcuts > Delete Profile. "User cannot delete the Profiles that are associated with Edges."
- **Assign to an Edge.** A Profile is chosen from a drop-down when an Edge is provisioned (Configure > Edges > Add Edge).

## The page, the tabs and the list

The Profile page names two tabs, **Device** and **Overview**. The Overview shows all the Profile's configuration, including the Edge models enabled for it, the configured network services and the assigned segments. The business policy and firewall pages refer to a **Business Policy** tab and a **Firewall** tab of the Profile; the Profiles list reaches them with the **Biz. Pol** and **Firewall** View links, so the pages word it differently. The list's columns are Name, **Used By** (the number of Edges), Biz. Pol and Firewall; its toolbar has New Profile, Duplicate, Modify, Download (all Profiles to an Excel file) and More.

## What a Profile change does

The Profile pages say only that a Profile is a template applied to many Edges and that interface settings are applied automatically to the associated Edges (<Term id="inheritance">inheritance</Term>), with an <Term id="override">Override</Term> possible per Edge. The Appendix lists which configuration changes restart the Edge service (a brief traffic interruption; in an HA pair a failover). When an Edge is moved to another Profile only a few effects are documented (Section 4). Whether a later Profile edit reaches an Edge that overrides that setting is not stated.

## Settings reference

| Field | What it does | Allowed values and default |
|---|---|---|
| Name | names the Profile | entered in the New Profile dialog and editable on the Overview tab |
| Description | free text | entered with the name |
| <Term id="local-credentials">Local Credentials</Term> | the Profile's local credentials (Overview tab, EDIT) | default is a random password; at least 8 and fewer than 32 characters, one number and one lowercase character |
| Used By | the number of Edges using the Profile | list column |
| Overview | all configurations of the Profile in one view | tab; includes Edge models, network services and segments |
| Copy Profile | duplicates a Profile | a dialog; its fields were not described |
| Download | exports all Profiles to an Excel file | list toolbar |

## Key takeaways

- Create with New Profile, duplicate with Duplicate or Copy Profile, modify through Modify or the Overview tab, delete only when no Edge uses it.
- The Profile page has Device and Overview tabs; Biz. Pol and Firewall are View links in the list.
- A Profile is assigned to an Edge when the Edge is provisioned; interface settings flow automatically unless overridden.
- What a change does to Edges is only partly documented.

## What would you look for in the VCO

- Which Profile does this Edge use, and how many Edges share it?
- Which tab holds the setting I am looking for?
- Does the change restart anything?
