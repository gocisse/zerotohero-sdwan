**By the end of this lesson you will be able to:**

- name the Edge hardware families in the current datasheets and say what each datasheet row tells you;
- explain why a throughput figure comes with conditions, and why the software release matters;
- say which published figure answers a design question (tunnels, flows, segments, interfaces, availability);
- shortlist a model for a site and list what the datasheets do not tell you.

## What a datasheet is

A datasheet is the vendor's table of published limits for a product family at a point in time. Two Arista datasheets cover the Edge hardware on sale: one for the **7x0 series** (Edge 710-W, 710-5G, 720 and 740) and one for the **4100 and 5100**. Both were dated October 2026 (document numbers 04-0063-07 and 04-0062-06) when we read them, and both say the performance figures need software release **R7.0.0**. Virtual Edges have their own tables in the 7x0 datasheet.

<Callout variant="info" title="How this lesson tags figures">
  A figure marked **(datasheet)** is printed in one of the two datasheets above. A sentence marked **(design practice)** is our reasoning about how to use a figure and is not a vendor statement. Model families change: read the current datasheet before you quote a number.
</Callout>

## The rows that matter

| Row | What it tells you |
|---|---|
| Connectivity (LAN / WAN ports) | how many ports of each type, for example 1G RJ-45, 2.5G RJ-45, SFP+, SFP28, QSFP |
| Max throughput per Edge | the highest rate measured, under stated conditions (large 1300-byte packets or <Term id="imix">IMIX</Term>, a mix averaging 417 bytes, with DPI on) |
| <Term id="max-tunnel-scale">Max tunnel scale</Term> | how many tunnels the Edge supports; this is the figure a Hub needs |
| Flows per second, max concurrent flows | how fast new flows can start and how many can be open at once |
| Max segments | the hardware ceiling for <Term id="segment">segments</Term> |
| Editions table | features and limits that depend on the software edition, not the hardware |
| <Term id="bandwidth-tier">Bandwidth tiers</Term> | the licensed bandwidth levels each model can be sold with |
| Enhanced HA link performance | the throughput across the link between the two Edges of a pair |

The 710-W also has integrated Wi-Fi and the 710-5G integrated 5G/LTE (datasheet). The 7.0 Administration Guide gives the same kinds of figures for earlier models such as the 840 (for example 128 segments and 1.9 million concurrent flows); those older models are on the lifecycle list rather than the current datasheets.

## What the limits mean in a design

- **Throughput** (design practice): compare it with the total bandwidth you will actually run through the Edge with the services on, and keep headroom. The vendor's older guide says its test results "are not all-inclusive metrics, nor are they performance or scale limits".
- **Tunnels** (design practice): a branch with a few tunnels rarely worries about this row. A Hub, which every spoke builds a permanent tunnel to, is where it decides the model. Section 5 explains Hubs.
- **Flows and segments**: a site with many users or many <Term id="segment">segments</Term> checks the flow rows and the segment row. The edition can lower the segment limit as well: the Standard edition lists 4 data segments and 128 for Enterprise and Premium (datasheet).
- **Availability**: both datasheets list high availability for the Edge and an enhanced HA link figure, for example 1 Gb/s for the 720 and 10.8 Gb/s for the 4100. HA needs two Edges of the same model; Lesson 5 covers it.
- **Licence versus hardware**: bandwidth is licensed in tiers (the 710 up to 500 M, the 720 up to 10 G, the 5100 from 10 G to 100 G, datasheet), so the licence can be lower than the hardware ceiling.

## Choosing a model: a shortlist method

(design practice) Work through these in order and keep the shortlist as a list of models, not one answer:

1. **Role**: branch Edge or Hub? A Hub starts from the tunnel row.
2. **Transports**: how many WAN links and what speed and media? Check the connectivity row for ports of the right type.
3. **Throughput with headroom** for the services you will turn on.
4. **Flows and segments** for the users and the segment plan.
5. **Availability**: one Edge or a pair of identical models.
6. **Software**: the figures assume R7.0.0, so check the release you run.

<Callout variant="warning" title="What the datasheets do not tell us">
  The course outline describes a large-branch model with eight interfaces but names no model. In the datasheets the 720 and 740 each list eight data ports (six 2.5G RJ-45 and two SFP+), while the 4100 and 5100, which Arista positions for large branches, regional hubs and data centers, list eighteen and sixteen; the earlier Edge 840 is reported with eight only by retailers. So "eight interfaces" is confirmed for two models but does not identify a large-branch model. The 7.0 Edge device settings page lists the models that can host a security VNF (520v, 840, 620, 640 and 680); the current 7x0, 4100 and 5100 are not in those tables and the datasheets list VNF hosting only as a software feature, so VNF support on them is not documented in the pages we read.
</Callout>

## What you would see in the VCO

- **Configure > Edges**, then an Edge, then its **Device** tab: **Interface Settings** lists the Edge's interfaces; an interface is a Switch Port, a Routed Interface or a WLAN Interface depending on the model, and **Enable WAN Overlay** is a checkbox per interface.
- The **High Availability** section of the same tab holds the HA choices.
- **Monitor > Network Overview > Configuration Data** shows software versions, segments and HA and VNF flags across the Enterprise.
- Where the model name itself is displayed was not documented in the pages we read.

<Callout variant="tip" title="Check this in your own VCO or site">
  - **[observation candidate]** Open: Configure > Edges, one Edge, Device tab, Interface Settings. Expect: the interface list matches the datasheet's port counts for that model (for example GE and SFP names). Docs may differ: the datasheet counts physical data ports; the VCO may also show management or virtual interfaces.
  - **[observation candidate]** Open: Configure > Edges and the Edge's page header or list columns. Expect: the model name is visible somewhere. Docs may differ: the exact screen is not documented in the pages we read.
  - **[observation candidate]** Open: Monitor > Network Overview > Configuration Data. Expect: the software version of each Edge is listed; compare it with R7.0.0, the release the datasheet figures assume. Docs may differ: your VCO may run a 6.x release.
  - **[observation candidate]** Open: Configure > Segments, then count the segments an Edge's Profile includes. Expect: no more than the model's published maximum (for example 32 on a 710). Docs may differ: the pages do not say what the VCO does when a model's limit is exceeded.
</Callout>

## Key takeaways

- Current hardware: the 7x0 series, the 4100 and the 5100, plus Virtual Edges; the figures assume R7.0.0.
- Read a throughput figure together with its conditions; tunnels, flows, segments and ports have their own rows.
- A Hub is sized by tunnel scale first; availability needs two identical models.
- Edition and licence limits are separate from hardware limits.

## What would you look for in the VCO

- Which model and which software release is this Edge?
- How many segments, tunnels and interfaces does it use against the published limit?
- Is it part of an HA pair, and are both Edges the same model?
