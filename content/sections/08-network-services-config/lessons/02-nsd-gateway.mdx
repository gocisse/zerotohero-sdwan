- follow the documented order for creating an NSD via Gateway and assigning it;

- say what to look at afterwards, and which fields the documentation leaves open.

## The documented order

A <Term id="nsd-via-gateway">Non SD-WAN Destination via Gateway</Term> is a destination such as a cloud provider, firewall or data center that a Gateway reaches with an <Term id="ipsec">IPsec</Term> tunnel. The documented steps are:

1. **Configure > Network Services**, expand **Non SD-WAN Destinations via Gateway**, select **New** ("New NSD via Gateway" appears only when the table is empty).
2. Enter the general fields below and select **Create**.
3. The page opens the settings for the chosen type. Complete them and select **Save Changes**.
4. **Assign it to a Profile**: Device tab > VPN Services > turn **Cloud VPN** on > under Edge to Non SD-WAN Sites select **Enable Edge to Non SD-WAN via Gateway**, choose the destination and **Add** (or **New Destination**).

The types labelled Route Based VPN are <Term id="route-based-vpn">route-based</Term>, and the Generic Firewall type is <Term id="policy-based-vpn">policy-based</Term>. The Gateway is the tunnel **initiator**; it cannot be the responder. An NSD via Gateway is defined exclusively at the Profile level, so an Edge cannot override it. The documentation says the data center administrator must configure the Gateway side and activate the data center tunnel first.

## Settings reference

General fields, in the order of the form (documented defaults only):

| Field | What it does | Allowed values and default |
|---|---|---|
| Name | names the destination | free text |
| Type | the IPsec peer type; fixed after creation | AWS VPN Gateway, Check Point, Cisco ASA, Cisco ISR, Generic IKEv2 Router (Route Based VPN), Microsoft Azure Virtual Hub, Palo Alto, SonicWall, Zscaler, Generic IKEv1 Router (Route Based VPN), Generic Firewall (Policy Based VPN) |
| Tunnel Mode | how many tunnel endpoints are used | Active/Hot-Standby: up to 2; Active/Active: up to 4 |
| Load Sharing Method (ECMP) | how flows map to the active paths | Flow Load Based (default) or Hash Load Based |
| VPN Gateway 1 | the primary peer | a valid IP address, required |
| Secondary VPN Gateway | an additional peer, created on Save Changes | not supported for Cisco ASA and Generic Firewall |
| Site Subnets | the subnets behind the destination | a toggle with Add and Delete |

The tunnel limits depend on the type: up to 4 Active/Active and 2 Active/Hot-Standby for AWS VPN Gateway, Check Point, Cisco ISR, Generic IKEv2, Palo Alto, SonicWall, Zscaler and Generic IKEv1; 2 and 2 for Azure Virtual Hub; 1 for Cisco ASA and Generic Firewall. "If there are no site subnets configured, deactivate Site Subnets to activate the tunnel." For a data center destination, local subnets must also be configured.

### The AWS VPN Gateway type

The documented fields for the AWS type (the Generic IKEv2 type has the same set) are:

| Field | What it does | Allowed values and default |
|---|---|---|
| Enable Tunnel(s) | lets the Gateway initiate the tunnels | toggle |
| PSK | the pre-shared key | generated by the Orchestrator unless you enter your own |
| Encryption | tunnel encryption | AES-128 (default) or AES-256 |
| DH Group | key exchange group | 2 (default), 5 or 14 |
| PFS | perfect forward secrecy | Deactivated, 2 (default) or 5 |
| Authentication Algorithm | integrity hash | SHA1 (default), SHA256, SHA384 or SHA512 |
| IKE SA Lifetime (min) | lifetime of the IKE security association | 10 to 1440, default 1440 |
| IPsec SA Lifetime (min) | lifetime of the IPsec security association | 3 to 480, default 480 |
| DPD Type | dead peer detection mode | Periodic or onDemand (default) |
| DPD Timeout (sec) | added to an internal timer | from 5.1.0 the minimum interval is 47.5 seconds plus this value; 0 no longer disables DPD |
| Redundant VeloCloud Cloud VPN | adds redundant tunnels per VPN Gateway | checkbox |
| Local Auth Id | the local identity of the tunnel | FQDN, User FQDN, IPv4 or IPv6; blank uses a default |
| Location | latitude and longitude used to choose the nearest Edge or Gateway | Edit |

For AWS-initiated rekey failures the guide says to set the IPsec SA Lifetime below 60 minutes (50 recommended) and to match the DH Group and PFS on both sides.

### BGP over IPsec

The **BGP** column of the list has an Edit action. Only **eBGP** is supported with <Term id="bgp-over-ipsec">BGP over IPsec</Term>. The BGP Editor documents these fields:

| Field | What it does | Allowed values and default |
|---|---|---|
| Local ASN | the Gateway-side autonomous system number | not stated |
| Router ID | the BGP router ID | not stated |
| Neighbor IP | the NSD neighbour's address | an IP address |
| ASN | the neighbour's autonomous system number | not stated |
| Local IP | source address for the neighbour; mandatory for Non SD-WAN neighbours | not stated |
| Max-hop | hop limit, shown only for eBGP | 2 to 255 (5.1 and later), default 2 |
| Keep Alive | keep-alive interval | 0 to 65535 seconds, default 60 |
| Hold Timer | peer considered down after this time | 0 to 65535 seconds, default 180 |
| Connect | connect interval | seconds, default 120 |
| Inbound Filter | filter for routes from the neighbour | select from the list |
| Outbound Filter | filter for routes to the neighbour | select from the list |

The default Tunnel Mode and the default state of Enable Tunnel(s) are not stated. In the text we read the Cisco ASA table lists a Tunnel Mode while the limits table gives it a single tunnel. Check these in your own release.
</Callout>

## What you would see in the VCO

- **Configure > Network Services > Non SD-WAN Destinations via Gateway**: the list with BGP and BFD columns, Edit, Operator Alerts and a Conceptual Destination Diagram.
- **Configure > Profiles > (Profile) > Device > VPN Services**: Cloud VPN and the Edge to Non SD-WAN Sites checkbox.
- **Monitor > Events**: "BGP session established to Gateway neighbor" and "Unavailable Gateway BGP neighbor".
- **Diagnostics > Remote Diagnostics > MTR**: a path choice of NVS via Gateway when one is configured.

<Callout variant="tip" title="Check this in your own VCO">
  - **[observation candidate]** Open: Configure > Network Services > Non SD-WAN Destinations via Gateway, New. Expect: the Type list shows the eleven types above, and Tunnel Mode offers Active/Hot-Standby and Active/Active. Docs may differ: your release may show fewer types or add one.
  - **[observation candidate]** Open: an existing NSD of type AWS VPN Gateway, its settings. Expect: Encryption AES-128, DH Group 2, PFS 2 and IKE SA Lifetime 1440 unless someone changed them. Docs may differ: defaults are as documented for 6.4 and 7.0; your release may differ.
  - **[observation candidate]** Open: the NSD list, the BGP column Edit. Expect: a BGP Editor with Local ASN, Router ID and a Neighbors area, and Max-hop 2 by default. Docs may differ: the exact layout.
  - **[observation candidate]** Open: Monitor > Events after a BGP session to the NSD comes up. Expect: a "BGP session established to Gateway neighbor" event. Docs may differ: the exact wording.
  - **[observation candidate]** Open: the Profile's VPN Services section. Expect: the destination listed under Edge to Non SD-WAN Sites. Docs may differ: it may be assigned in another Profile.
</Callout>

## Key takeaways

- Create the NSD, complete its type settings, then assign it in the Profile; the Edge cannot override it.
- The Gateway initiates the tunnels; the type decides how many tunnels are possible.
- The AWS and Generic IKEv2 types share one documented field set with defaults.
- BGP over IPsec is eBGP only; verify with the Monitor events.

## What would you look for in the VCO

- Which Type and Tunnel Mode does this NSD use, and does the tunnel limit allow that?
- Are the Site Subnets right, or deactivated on purpose?
- Is the NSD assigned in the Profile of the Edge you are looking at?
