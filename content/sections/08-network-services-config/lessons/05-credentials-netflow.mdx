**By the end of this lesson you will be able to:**

- create API Credentials for Azure and Zscaler with the fields the documentation names;
- configure a <Term id="collector">NetFlow collector</Term> and <Term id="flow-filter">filter</Term> and assign them in a Profile and an Edge;
- state the NetFlow limits and the documented defaults;
- say what to check when a collector receives nothing, and what the documentation leaves open.

## API Credentials

**Configure > Network Services > API Credentials** has two lists. **IaaS Subscriptions** are for Microsoft Azure and **Cloud Subscriptions** are for Zscaler. A subscription is what an Azure NSD (Lessons 2 and 3) uses to read your Azure Virtual WAN and hubs, and a **Validate Subscription** or **Get Subscriptions** action checks the details.

Azure needs tenant ID, client ID and secret; Zscaler uses a different set (name, cloud, partner admin credentials, API key and domain).

## NetFlow

The Edge sends IPFIX (version 10) flow records, aggregated by source IP, destination IP, destination port and protocol, to **collectors**. The documented order is:

1. **Configure > Network Services > Network Management > NetFlow.** Under Collectors select **New**, enter the fields and Save Changes. Under Filters select **+New**, set a Match and an Action and OK.
2. **Profile:** Configure > Profiles > (Profile) > Device > **Telemetry > NetFlow Settings**; choose the segment first, tick **Activate NetFlow**, pick a collector (or + New Collector) and optionally a filter.
3. **Edge:** Configure > Edges > (Edge) > Device > Telemetry > NetFlow Settings; choose the segment, select **Override** and set the **Source Interface**.

<Diagram id="svc-netflow-path" />

**Limits:** 2 collectors per segment, 8 per Profile and per Edge, 16 filters per collector. Filters do not apply to SD-WAN Control, Overflow or Private data. Intervals are configured on the Global segment only. NetFlow needs at least one up and advertised LAN or routed interface on the segment, and without a Source Interface the Edge may not generate NetFlow packets.

## Settings reference

### API Credentials

| Field | What it does | Allowed values and default |
|---|---|---|
| Subscription Type | the kind of subscription | fixed: Microsoft Azure (IaaS) or Zscaler (Cloud) |
| Active Directory Tenant ID | your Azure <Term id="tenant-id">tenant</Term> | from Azure; no default |
| Client ID | the Azure application's <Term id="client-id">client ID</Term> | from Azure; no default |
| Client Secret | the application's secret | from Azure; a less-than sign is not supported from release 4.5 |
| Subscription Name | names a Zscaler subscription | free text |
| Zscaler Cloud | which Zscaler cloud | newCloud, zscaler.net, zscalerone.net, zscalertwo.net, zscalerthree.net, zscalerbeta.net or zscloud.net |
| Partner Admin Username | the Zscaler partner administrator | from Zscaler; the password cannot contain a less-than sign from 4.5 |
| API Key | the Zscaler API key | minimum 12 alphanumeric characters |
| Domain | the Zscaler domain | a valid domain name |

### NetFlow

| Field | What it does | Allowed values and default |
|---|---|---|
| Collector Name | names the collector | unique |
| Collector IP | where records are sent | an IP address |
| Collector Port | the collector's port | not stated |
| Filter Name | names the filter | unique |
| Match | which flows the filter covers | Define (source IP, destination IP or application) or Any |
| Action | what the filter does | Allow or Deny |
| Activate NetFlow | turns export on for the segment | checkbox, IPFIX version 10 only |
| Allow All | sends all segment flows to that collector | checkbox per collector; an implicit "Allow All" rule ends each filter list |
| Flow Stats | export interval of flow statistics | 60 to 300 seconds, default 60 |
| Tunnel Stats | export interval of tunnel statistics | 60 to 300 seconds, default 60 |
| Interface Table | export interval of the interface option table | default 300 seconds |
| Source Interface | the Edge interface used as the source | a non-WAN interface (Loopback, VLAN, Routed or Sub-Interface) with Advertise enabled |

<Callout variant="warning" title="Fields we could not confirm">
  The pages we read give no default collector port, no status or event for NetFlow, and no export counter, and they do not say how Allow All and Deny interact beyond the implicit Allow All at the end of the list. For API Credentials there is no status or role information either.
</Callout>

## What you would see in the VCO

- **Configure > Network Services > API Credentials** and **Network Management > NetFlow**: the lists.
- **Configure > Profiles > (Profile) > Device > Telemetry > NetFlow Settings** and the same section on the Edge with Override.
- The documentation names no NetFlow event or Monitor screen.

<Callout variant="tip" title="Check this in your own VCO">
  - **[observation candidate]** Open: Configure > Network Services > API Credentials, New under IaaS Subscriptions. Expect: Subscription Type Microsoft Azure, Active Directory Tenant ID, Client ID and Client Secret, and a Get Subscriptions action. Docs may differ: labels may vary slightly.
  - **[observation candidate]** Open: the same page, New under Cloud Subscriptions. Expect: Subscription Name, Zscaler Cloud, Partner Admin Username and Password, API Key and Domain. Docs may differ: your release may list other clouds.
  - **[observation candidate]** Open: Network Management > NetFlow, New under Collectors. Expect: Collector Name, Collector IP and Collector Port with no default port. Docs may differ: your release may pre-fill a port.
  - **[observation candidate]** Open: a Profile's NetFlow Settings. Expect: Activate NetFlow, a collector list with Allow All, intervals of 60 and 300 seconds. Docs may differ: intervals are configured on the Global segment only.
  - **[observation candidate]** Open: an Edge's NetFlow Settings after Override. Expect: a Source Interface list of non-WAN interfaces and a read-only Observation ID. Docs may differ: the list depends on the Edge's interfaces.
</Callout>

## Key takeaways

- Azure credentials are tenant ID, client ID and secret; Zscaler credentials are a different set.
- NetFlow is collectors, filters, then activation in a Profile with an Edge override and a Source Interface.
- Limits: 2 collectors per segment, 8 per Profile and Edge, 16 filters per collector.
- No default port, status screen or event is documented for NetFlow.

## What would you look for in the VCO

- Is NetFlow activated for the segment, and which collector and filter does it use?
- Does the Edge have a valid Source Interface?
- Are the credentials validated, and which subscriptions use them?
