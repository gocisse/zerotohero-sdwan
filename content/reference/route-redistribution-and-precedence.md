# Route redistribution, route preference and the checks of third-party statements

Read 2026-10-19. The Arista pages never use the term "administrative distance" (the 7.0 Overview and routing pages were searched; the tool reported it absent). The equivalent is a fixed **order of operations** plus a numeric **route preference** (lower wins). Numbers below come from the 7.0 Overview "Preference Values" table, copied as printed by the summarising tool in two separate reads.

## Third-party outline statements: result

| statement | verdict | what the sources say |
|---|---|---|
| Admin distances (or equivalent) differ between OSPF, BGP and overlay routes and decide route selection | **Corrected** | No "administrative distance" in the pages read. Selection is a fixed order of operations (longest prefix, connected, local static, NSD, remote Edge routes, then dynamic routes) and, inside dynamic routes, numeric route preferences (lower wins; defaults for OSPF intra 1001, inter 1002, eBGP 1003, iBGP 1004) set by OFC or DCC, then protocol attributes, Logical ID and age. Documented in 7.0; 6.4 not read for this table. |
| OSPF E1 versus E2 and the default metric type for redistributed routes | **Confirmed** | Metric type E1 or E2; default E2; default metric 20. Same in 6.4 and 7.0. Route type order among OSPF-learned routes: intra, inter, E1, E2. |
| Default redistribution between overlay and OSPF; mutual redistribution must be enabled explicitly | **Partly confirmed, partly unconfirmed** | OSPF-learned routes automatically go to the Gateway (6.4 and 7.0), subject to the Global Advertise Flags (External OSPF off by default). Overlay routes into OSPF need the Overlay Prefixes checkbox; BGP into OSPF needs the BGP option; default states not stated. |
| Route summarization of OSPF routes before advertising into the overlay | **Corrected** | The OSPF Route Summarization table (Subnet, No Advertise, Tag, Metric Type, Metric) is about external (Type-5) routes under a supernet. Summarization of OSPF-learned routes before the overlay is not described. |
| BGP attribute manipulation (local preference, MED, AS-path prepend) via filters or route maps, inbound and outbound | **Confirmed with corrections** | Done with neighbor Inbound and Outbound Filters (not named route maps): Local Preference, Metric (MED), Community, As-Path-Prepend and As-Path-Exclude. As-Path-Prepend appears in the 7.0 underlay filter options; the 6.4 text read mentions it only in the NSD and Gateway sections. For iBGP to NSD, local preference cannot be set by an outbound filter. |
| The BGP network statement versus redistribution of connected routes | **Partly confirmed** | The Default Route option adds a network statement; a Networks field lists addresses BGP advertises; Connected Routes is a separate redistribute checkbox. Whether the Networks field is a general network statement for any prefix is not stated beyond its description. |
| OSPF on routed interfaces versus VLAN/SVI interfaces | **Confirmed** | Full OSPF functionality needs routed interfaces; on a switched (VLAN) interface the Edge supports OSPF only as passive. Profile text says LAN only; Edge text says LAN (routed or switched) or WAN; both 6.4 and 7.0. |
